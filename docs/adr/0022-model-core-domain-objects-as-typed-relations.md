# Model core domain objects as typed relations

V1 models authoritative Account, Deal, source, Evidence, judgment, analysis, process, Deliverable, Revision, authorization, Job, commercial, audit, and retention concepts as explicit PostgreSQL relations with typed columns, tenant-bearing keys, foreign keys, uniqueness, checks, and Row Level Security rather than a generic domain-object table, entity-attribute-value model, or JSON document store. Versioned JSONB is limited to schema-governed boundary payloads whose structure legitimately varies by file format, provider, manifest, locator, or capability profile; permissions, lifecycle state, object identity, financial amount semantics, version relations, and authorization never exist only inside JSONB. This accepts more deliberate migrations and tables in exchange for database-enforced isolation, referential integrity, auditability, and safe evolution of the financial workflow model.
