# Validated Self-Serve Deal Workspace First-Value Journey

Status: validated by the user on 2026-08-01

## Question settled

What product form and interaction sequence let an overseas Individual Banker discover, purchase, create a first Sell-Side Auction Deal, supply the minimum authorized sources, supervise evidence-bounded AI and deterministic work, correct results, obtain a Controlled Auction Execution Package, authorize an exact Revision, export it, and return after a new Deal event without offline sales, implementation, Banker advisor, or support-operated work?

## Verdict

Use a deliberately asymmetric synthesis:

> **C owns discovery and outcome comprehension; A owns first correct use inside the product; B is the durable Deal Workspace shell.**

The validated prototype route is [H — Validated Hybrid, C → A → B](self-serve-first-value-journey-prototype/README.md#validated-synthesis). A/B/C remain the primary comparison evidence; H records the user-confirmed synthesis.

This is not three permanent peer products. The persistent Deal Workspace is the authoritative product object. Guided first use and Package Readiness are modes within that object, entered because of lifecycle context rather than exposed as disconnected tools.

## Validated product form

### C — outcome-first discovery

Public discovery leads with the Controlled Auction Execution Package and its controlled artifact family: Analysis & Valuation Workbook, Auction Control Workbook, stage-triggered marketing and decision artifacts, exact reader copies, evidence/control records, and archive package. Product proof shows one material number from exact source locator through proposed Fact, workbook cell, CIM statement, and exact reader copy.

The discovery surface must state who the product serves, the Sell-Side Auction outcome, the self-serve purchase path, and the boundary between software purchase, authority to use Deal material, source truth, professional suitability, and external-use authorization. Pricing remains a placeholder until the monetization decision is resolved elsewhere.

### A — guided first correct use

After checkout, the product opens a recoverable First Deal Guide **inside** the persistent Deal Workspace. The guide sequences only the controls required to reach first value safely. It remains reopenable, shows completed and blocked steps, and routes exceptions to the exact Evidence, Source Record, deterministic result, or Human Decision that can recover them.

The guide is not a separate onboarding application and does not require an offline implementation session. It ends at a product-defined first-value milestone, not at “account created,” “files uploaded,” or “AI draft generated.”

### B — durable Deal Execution Desk

The Deal graduates into the persistent execution desk when the first-value milestone is achieved. B becomes the stable shell for Deal Brief, Event Inbox, Sources, Work Queue, Evidence & Decisions, Analysis, Execution Package, QC & Readiness, and History & Export. It supports return, parallel work, exception recovery, new Source Records, Impact Assessments, and immutable Revisions without forcing an experienced user through a linear wizard on every visit.

### C retained inside B

Execution Package / Readiness retains C's artifact-first information architecture as a core B workspace view. It lets the Banker inspect the package spine, each artifact's source and decision dependencies, output ceiling, reader representation, QC posture, exact Revision, External-Use Decision, and archive/export state. It must not collapse into a generic file-generation screen.

## Validated first-value sequence

1. **Discover the outcome.** Identify the Individual Banker, Sell-Side Auction Job to Be Done, Controlled Auction Execution Package, inspectable synthetic proof, and self-serve path.
2. **Complete simulated purchase.** Keep purchase authority distinct from authority to upload, process, rely on, or disclose Deal material.
3. **Create the Deal.** Bind Deal identity, transaction subject, Sell-Side role, Preparation stage, currency, and intended use.
4. **Confirm authority and confidentiality.** Record upload/use authority, permitted processing and derived work, confidentiality posture, source rights, and intended audience boundary.
5. **Select the minimum exact Source Packet.** Start upload/export-first with exact Source Records, versions, native locators, freshness, parse coverage, conflicts, rights, and reliance ceilings visible.
6. **Authorize the work objective.** State the selected source perimeter and separate AI proposals, deterministic closure, and Banker decisions.
7. **Run observable controlled work.** Show ingestion, extraction, analysis, deterministic validation, and deliverable generation as independent, recoverable lanes rather than one aggregate percentage.
8. **Reach unmistakable first value.** Surface a material conflict and deterministic failure with exact lineage; let the Banker correct, decide, and see the affected output/control state recover.
9. **Graduate into the execution desk.** Preserve the guide and its event history, but make the persistent work-domain shell the normal operating surface.
10. **Complete remaining control work.** Resolve other source, parse, rights, Claim, Assumption, conflict, Impact Assessment, QC, professional suitability, and circulation blockers.
11. **Review the controlled package.** Inspect editable native artifacts, exact reader copies, evidence/control records, readiness posture, and archive manifest.
12. **Record exact-version external use.** Bind Revision, hashes, audience, purpose, time, conditions, and decision-maker; circulation candidate remains distinct from authorization and from transmission.
13. **Export and return.** Simulate native/reader/archive export, return on a new Source Record or Deal event, fork a new Revision, recalculate/regenerate/re-review only affected scope, and require new future-use authorization.

## First unmistakable value moment

The first-value milestone is the closed control loop around two synthetic material exceptions:

- `SR-001 Draft_CIM_v3.pdf`, display page 18 Table 4, reports a seller Claim of `$18.4m` Adjusted EBITDA.
- `SR-002 Management_Model_v7.xlsx`, `Operating Case!F42`, reports `$17.8m` and creates a material conflict rather than silently overwriting either value.
- AI extraction version 1 records Cash as `$6.2m`; the visible native locator `SR-002 / Balance Sheet!F28` shows `$4.7m`, producing a `$1.5m` EV-to-equity tie-out failure.
- The Banker records `$17.8m` as the controlling treatment for the stated Rev 0.3 valuation purpose while retaining the `$18.4m` seller Claim, corrects Cash to `$4.7m` as a new version, accepts the bounded Cash Fact, and reviews the Impact Assessment.
- Deterministic tie-out recovers and the product shows the affected Analysis Workbook cells, valuation outputs, CIM statement, exact reader copy, QC, readiness, and prior-authorization consequences.

This moment proves both time-saving execution and professional control before the entire package is finished. A generated draft, completed upload, dashboard percentage, or attractive reader preview alone is not first value.

## Required user inputs and decisions

### Inputs

- purchase/evaluation authority for the self-serve transaction;
- Deal identity, entity, role/side, business stage, currency, and intended use;
- upload/use authority, permitted processing, confidentiality posture, source rights, intended audiences, and restrictions;
- exact upload/export-first Source Records and explicit Source Packet selection;
- work objective and selected source perimeter;
- correction value and correction reason when extraction is wrong;
- exact Revision, audience, purpose, decision time, conditions, and decision-maker for external use.

### Typed Banker decisions

- accept or reject a proposed Fact for a stated scope and purpose;
- approve a bounded Assumption without converting it into a Fact;
- resolve a material source conflict while preserving both source histories;
- exclude or request support for an unsupported Claim;
- review the Impact Assessment and choose recalculation, regeneration, re-review, or continued blocking;
- judge Professional Usability and promote an eligible Revision to circulation candidate;
- record an exact-version External-Use Decision.

No generic “Approve AI” action may substitute for these distinct decisions.

## Failure and recovery behavior

Every material exception must expose why the affected work is blocked, the exact objects and downstream artifacts affected, what work may continue, the required recovery action, and the state to which work returns. The prototype validated recovery for:

- material Source Record missing;
- stale or conflicted source;
- material parse/OCR limitation;
- deterministic tie-out failure that cannot be waived;
- unsupported Claim;
- reader-facing rights/confidentiality restriction;
- explicit circulation hold;
- incomplete Fact, Assumption, conflict, Impact Assessment, QC, professional-suitability, or exact-version external-use decisions.

Corrections preserve the original extraction and append a new version. A material change invalidates affected calculations, generated artifacts, QC results, readiness, and future-use authorization until the required recalculation, regeneration, targeted re-review, and decisions are complete. Unaffected work may continue when the missing-source consequence permits it.

## Return and repeat loop

The export receipt binds Rev 0.3 native artifacts, exact reader copies, evidence/control records, manifest, hashes, QC, and External-Use Decision. When `SR-006 July_Actuals.xlsx` arrives:

1. the Deal Workspace records a new exact Source Record and event;
2. an Impact Assessment identifies affected Facts, calculations, workbook cells, valuation outputs, CIM slides, reader copies, QC, readiness, and authorization;
3. Rev 0.4 forks from Rev 0.3 rather than overwriting it;
4. Rev 0.3 and its exact authorization remain immutable historical records;
5. affected Rev 0.4 scope is recalculated, regenerated, and re-reviewed;
6. Rev 0.3 authorization does not carry forward to Rev 0.4.

The same Deal Workspace therefore supports first use and repeated Deal events; repeat work is not a new disconnected AI session.

## Rejected alternatives

- **Pure A — Guided First-Deal Journey:** rejected as the durable shell because repeated and parallel Deal work would remain artificially linear. Retained as an embedded, recoverable first-use mode because it best protects correct self-serve activation.
- **Pure B — Deal Execution Desk:** rejected as the unaided first-use experience because the simultaneous work domains and control density impose too much initial cognitive load. Retained as the canonical product shell because it best supports persistent execution and return.
- **Pure C — Package Readiness Workbench:** rejected as the entire product because it can be mistaken for a controlled file factory and understate the Deal lifecycle. Retained for discovery and as the Execution Package / Readiness view because it makes premium value and output ceilings concrete.
- **Three permanent peer entry points:** rejected because users should not have to choose a product architecture. The lifecycle determines which mode is primary.
- **Chat-first or magic-AI form:** rejected because it hides source perimeter, deterministic closure, typed Banker decisions, readiness, and exact-version control.

## Prototype limitations

- The artifact is disposable low-fidelity UI code, not production architecture or a future code foundation.
- All Deal data is synthetic and fictional; no real Confidential Deal Material was uploaded.
- Purchase, upload, parsing, OCR, AI, calculations, Office/PDF generation, hashes, external use, export, and new-source arrival are simulated.
- State lives only in browser memory and resets on full refresh.
- The prototype does not validate production security, permissions, performance, model quality, Office fidelity, integration behavior, or persistent recovery.
- Pricing and packaging are placeholders; this verdict makes no monetization decision.
- The user validated product form and first-value sequence, not brand, visual design, production usability metrics, willingness to pay, or acquisition economics.
