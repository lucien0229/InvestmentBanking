# Envelope-encrypt Protected Deal Objects

Every Protected Deal Object, including accepted Source bytes, retained derived representations, Native Artifacts, Reader Copies, and controlled exports, is written to a new immutable Supabase Storage path using a versioned chunked AES-256-GCM envelope with a random per-object data-encryption key, and that key is wrapped by an environment-specific United States-region Google Cloud KMS key. A Quarantined Upload remains isolated under provider transport and at-rest controls only until safety processing succeeds; the worker then encrypts the accepted representation, records its envelope and byte identities, attaches it atomically to the applicable domain object, and schedules removal of plaintext staging. Production and test keys are separate, key rotation rewraps data keys instead of rewriting object bytes, plaintext is confined to bounded worker temporary storage, and searchable relational or derived Deal data remains explicitly dependent on Supabase encryption, Row Level Security, and minimization rather than being falsely described as application-encrypted.
