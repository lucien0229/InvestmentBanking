# Authorize workers through Job-scoped Runtime Principals

V1 gives the browser, control plane, dispatcher, light worker, heavy worker, signer, retention executor, backup executor, and Deployment Operator separate credentials and non-overlapping product responsibilities rather than sharing a Supabase service-role or storage master credential. A worker may obtain Deal access only by atomically claiming a Job through a database procedure that issues a short-lived Job Scope binding the Runtime Principal to the exact Account, Deal, permitted object set, operations, and expiry; result commitment revalidates that scope and current authorization before any domain transition. Browser code never receives provider or service credentials, Deployment Operators have no product content path, and Webhooks prove their own provider identity without inheriting user authority, accepting additional database roles and procedures to contain a compromised component.
