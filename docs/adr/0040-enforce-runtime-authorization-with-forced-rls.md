# Enforce runtime authorization with forced RLS

Every online product database role in V1 is a non-owner `NOBYPASSRLS` role, and every authoritative tenant-bearing table uses `FORCE ROW LEVEL SECURITY`; schema ownership and migration authority remain offline and never serve Web, API, Gateway, Worker, or operator traffic. Runtime purposes use separate database identities, transaction-local authorization context may be established only through allowlisted validating entry functions, and elevated functions are typed, fixed-`search_path`, non-public procedures rather than a generic bypass. This adds migration, procedure, pooling, and test complexity in exchange for making Account, Deal, Job, Recipient, and purpose scope a database-enforced boundary instead of an application convention that a broad service credential can bypass.
